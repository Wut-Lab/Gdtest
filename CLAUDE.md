## Workflow
1. Godot 4.6.3 (Linux, official build from github.com/godotengine/godot releases) is needed for
   testing and export. Web export needs only `templates/web_nothreads_release.zip` from the
   export templates `.tpz`, installed in `~/.local/share/godot/export_templates/4.6.3.stable/`.
2. Scenes, the tile set and the UI theme are generated by `tools/build_scenes.gd` (art by
   `tools/make_art.gd`, music and sounds by `tools/make_audio.py`). Edit those tools and rerun them rather than hand-editing `.tscn` files.
   Copy a tool into the project root to run it: `godot --headless --path . --script res://build_scenes.gd`,
   then delete the copy and run `godot --headless --path . --import`.
3. Levels are text maps in `levels/*.txt` (`. # = R W ^ P G H C * D Q J L K E X S V T B 1 2 3`; W = rubber wall, ^ = one-way block, H = extra
   heart, C = treasure chest, * = pixel (currency), D/Q/J/L/K/E/I/F/Z/U/O/Y/N/s/p/A/M/X = Dash/Ground Pound/Double Jump/Glide/Quick/Tele-hop/High Jump/Phase Jump/Shockwave/Stunning Landing/Grip and Go/Lucky Charm/Bounce House/Slow Burst/Potion Booster/Air Brake/Momentum/Heart Box ability cards, S = spike square obstacle, V = up-down spike square, T/B = wide platform with spikes on top/bottom, digits are red/yellow/blue teleport pairs), loaded by `scripts/level.gd`. Keep arrival pads off the main route.
   Random levels come from `scripts/level_gen.gd` (seeded; its header lists the guidelines that keep them beatable).
   The game fills any screen (stretch aspect expand; portrait swaps to a 544×960 base and
   zooms the camera) — check both orientations when changing layout.
4. Test with `tools/bot.gd` (copy to root, run headless); it must print `RESULT: WON`.
5. Publish: `tools/build_web.sh <godot> <out-dir in scratchpad>`, then publish `play.html` and
   `editor.html` with the engine files to the artifact URLs above (same `url` keeps the link).
   Test pages locally with a viewport meta wrapper; Godot needs `canvas:` set because the editor
   page has two canvases.
